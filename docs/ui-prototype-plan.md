# pidesk UI 原型规划（v1.0）

> 2026-09-10。由 **frontend-design** skill（Anthropic 官方，`agent/skill/frontend-design/`，junction 接入 Claude Code / Codex）驱动，按其方法论执行：锚定题材 → 两遍式规划（令牌系统 → 反模板审查）→ 组件基建 → 分屏原型规格。
> 教训输入：vtools（egui 手绘 UI）的美观度问题——本项目 UI 一律经本规划约束，禁止脱离令牌系统即兴绘制。
> 关联：product-plan.md §2 T6（UI 基建裁决）、§6.5（分屏索引）；桌面密度与色彩纪律参照 Wegent `wework/DESIGN.md`（Codex 系视觉规范，工作区在档）。

## 1. 设计简报（题材锚定）

- **产品**：pidesk——pi 驱动的桌面 AI 工作台。用户是开发者（主用中文，Windows 优先）；核心体验是**看着 agent 干活**：流式对话、工具调用过程、工作流节点推进。
- **形态**：桌面工具（非网页、非营销页）——密度、冷静、长时间盯屏不疲劳是第一约束。
- **题材视觉母体**：终端 / IDE / 日志流。界面的人格来自"过程感"，不来自装饰。
- **本职工作**：会话与工作流的"发起 → 观察 → 介入（审批/中止/重跑）"。

## 2. 令牌系统（第一遍：规划）

### 2.1 色彩（石墨层积 + 语义色纪律）

| 令牌 | 值 | 用途 |
|------|-----|------|
| `bg-0` | `#141517` | 应用底盘（导航栏/标题栏） |
| `bg-1` | `#1b1d20` | 面板/主工作区 |
| `bg-2` | `#222528` | 浮层/悬停/输入框 |
| `text-0` | `#e4e6e8` | 主文本 |
| `text-1` | `#9aa0a6` | 次级文本/占位 |
| `hairline` | `#2e3237` | 1px 分隔线（替代阴影与卡片描边） |
| `focus` | `#4c8dff` | **仅**焦点环/链接/选中窄条（Codex 系纪律） |
| `ok` / `err` / `warn` | `#3fb950` / `#f85149` / `#d29922` | 仅语义状态（成功/失败/警告），不得充当装饰 |

规则：彩 hex 全应用合计 ≤7 个；任何灰阶表面不用阴影区分层级，用 `bg-0/1/2` 层积 + hairline；暗色为题材默认（终端母体），不做亮色主题（M5 后再议）。

### 2.2 字体

| 角色 | 字族 | 说明 |
|------|------|------|
| UI 正文 | 系统栈：`Segoe UI` / `PingFang SC` / `Microsoft YaHei` | 不引入额外 webfont（CJK 渲染与授权） |
| 代码/数据 | `Cascadia Code` → `JetBrains Mono` 回退 | **仅**用于代码块、命令、路径、token 计数等真数据；不作小标签装饰 |

字阶（px）：`12`（meta）/ `13`（密集列表）/ **`14`（正文基线）** / `16`（区块题）/ `20`（页题）。正文行高 1.5，标题 1.2，段宽 ≤72ch。

### 2.3 布局概念

应用壳：左侧 220px 导航栏（会话/工作流/运行/配置，图标+文字 30px 行高）+ 主工作区 + 按需右侧 inspector（320px，仅运行/会话详情态）。

```
┌────────┬──────────────────────────────┬───────────┐
│ 导航栏  │  主工作区（随导航切换）          │ inspector │
│ 会话    │  （对话流 / 流程编辑 / 运行监视） │ （按需）    │
│ 工作流  │                              │           │
│ 运行    │                              │           │
│ 配置    │                              │           │
└────────┴──────────────────────────────┴───────────┘
```

对话流：单列 ≤72ch、左对齐；工具调用是**可折叠行**（hairline 分隔 + 缩进层级），不是卡片。

```
│ ● 你         帮我拉取 release 并分析变更        │
│ ──────────────────────────────────────────── │
│ ▸ ⚙ bash  curl api.github.com/…    ✓ 2.1s     │  ← 折叠行：图标+摘要+状态+耗时
│ ▸ ⚙ read  CHANGELOG.md             ✓ 0.3s     │
│ ● pi        本次发布包含 3 项变更：…（流式中 ▌）  │
├──────────────────────────────────────────────┤
│ [输入框……………………………………] [发送] [⏹]            │
└──────────────────────────────────────────────┘
```

### 2.4 原则

1. **中性承载一切**——灰阶做全部 chrome，彩色只表达语义；这是纪律不是口味。
2. **密度是工具的礼貌**——30px 行、hairline 分隔、紧凑可呼吸；拒绝大圆角卡片阵列。
3. **过程可见**——agent 正在做什么永远可见（运行点、工具折叠行、节点推进条），这是全应用唯一的"表演位"。
4. **动效只回答动作**——流式打字、展开收起、确认反馈；零装饰性入场动画。
5. **键盘优先**——所有动作有快捷键，焦点环 2px `focus` 蓝永不弱化。

## 3. 反模板审查（第二遍：对照 frontend-design 校准清单）

| 校准项（AI 默认俗套） | 本规划判定 |
|------|------|
| 暖米底 + 衬线大字 + 陶土色点缀 | ✗ 未采用——暗色由终端题材正当化 |
| 近黑底 + 单一荧光绿/朱红 accent | ✗ 未采用——灰阶层积底，蓝仅限焦点语义 |
| 报纸式 hairline 多栏 + 零圆角 | ✗ 未采用——hairline 只做行分隔不做版式骨架 |
| SaaS 卡片阵列（同圆角同阴影同渐变） | ✗ 未采用——列表行 + 缩进层级，无阴影 |
| ALL-CAPS eyebrow / 间隔号 meta / 破折号标题 / 全局等宽小标签 / 按钮"→" | ✗ 全部未采用——meta 用 12px `text-1` 常规大小写；等宽仅限真代码数据 |

**审查结论**：通过。剩余自由度（石墨具体色值、字阶微调）不投向任何默认俗套。

## 4. 组件基建（裁决 T6）

| 层 | 选型 | 说明 |
|----|------|------|
| 组件库 | **shadcn/ui**（Tailwind CSS + Radix primitives） | 公认 React 组件事实标准；源码内联可改，主题 = 本规划令牌映射到 CSS variables |
| Markdown | `react-markdown` + `remark-gfm` | 排版规则继承 shadcn typography，代码块走 `bg-2` + mono |
| 画布（M4） | React Flow | 深色画布主题令牌化，节点用折叠行语言而非彩卡 |
| 图标 | `lucide-react` | 线性 16px，与 hairline 语言一致 |
| 状态/表单 | shadcn form + zod | 配置中心表单校验 |

明确禁用：渐变装饰、玻璃拟态、彩色大圆角卡片、emoji 作功能图标。

## 5. 分屏原型规格

### 5.1 会话面板（M1）

- 空态：居中一段引导文案 + 三个历史会话入口；不放假插画。
- 对话流（见 §2.3 wireframe）；助手消息六要素 markdown；思考块默认折叠（`text-1` 12px 摘要行）。
- 工具折叠行三态：运行中（呼吸点）、成功（✓ + 耗时）、失败（`err` 色 + 展开看 stderr）；审批请求固着在输入框上方（批准/拒绝 + 风险摘要），不弹窗。
- 模型切换：输入框左下角 `provider/model:thinking` 菜单（13px，等宽仅模型 id）；compact/中止在输入框右侧图标位。
- 会话列表（导航栏二级）：按 cwd 分组，条目 = 名称 + 相对时间 + token 计数（mono 12px）。

### 5.2 配置中心（M2）

- 布局：左树（凭据/模型与中转/Skills/MCP/扩展）240px + 右表单 ≤560px。
- 凭据：password 输入 + 显示切换；保存后列表仅显 `sk-…last4`；风险动作（删除/更换）二次确认。
- MCP 编辑器：server 行 = 名称 + 传输 + 启停开关；新增/导入走确认步（明示"任意命令执行"风险原文）。
- 全部保存即时原子落盘，右上角轻提示（toast，3s 自散）。

### 5.3 工作流编辑（M3，无画布）

- 顶部流程链：`Start → [节点 chip]… → Output` 横向只读总览（chip = 13px 图标+名，点击滚动定位）。
- 主体：有序节点列表（拖拽排序）+ 选中节点的表单区；PiAgent 节点表单含会话策略/模型/输出策略三组互斥单选。
- 校验：链路连通性、变量引用存在性，错误内联标注（`err` 色左边条）。

### 5.4 运行监视（M3）

- 左：步骤时间线（当前节点呼吸点、完成 ✓、失败 ✕，点击定位右区）。
- 右：节点输出流（日志/对话/工具折叠行同会话语言）；底部 context inspector（tab：context JSON / 变量 diff / 成本 tokens·cost mono 表）。
- 顶栏常驻：Run 状态 + 已用时长 + 取消按钮。

### 5.5 画布（M4）

- React Flow 深色令牌化：节点 = 紧凑框（标题 + 状态点 + 关键参数一行），连线 `hairline`，选中边 `focus` 蓝；分支节点出现前保持单链布局。

## 6. 质量底线与验收

- 底线：文本对比度 ≥4.5:1；可见焦点环；`prefers-reduced-motion` 尊重；窗口最小 960×640 可用；全部动作有键盘路径。
- 验收：M1 出口做一次对照走查（本规划 vs 实现截图），任何偏离令牌系统的样式需走裁决修订本档；vtools 美观度问题以"对照 Wegent DESIGN.md 密度/色彩纪律 + 本规划通过"为关闭标准。
